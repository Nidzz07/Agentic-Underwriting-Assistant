### Q1 — Feature-vector construction + how CON-BR1's demographic-exclusion is enforced **by construction**

### Q2 — IsolationForest seeding / determinism: is a fixed `random_state` the whole decision, given scikit-learn's cross-version behavior?

**Context**: CON-DET-1 + skill #5 require **identical input → identical output, 100%**. A fixed `random_state=<seed>` makes IsolationForest deterministic **for a fixed sklearn version + fixed data + fixed hyper-parameters**. But scikit-learn does **not** guarantee **cross-version** numerical reproducibility — a sklearn upgrade can change tree splits (and SHAP values) even with the same seed. The corpus `CorpusManifest` already records a `seed` and an `engine_version`; the audit tuple already versions `rulebook_version`/`model_version`/`engine_version`. So the open question is whether determinism is **`random_state` alone**, or **`random_state` + a pinned/recorded sklearn version** (a `sklearn_version` provenance field, analogous to `engine_version`).

- **A.** **`random_state` seed (sourced from the `CorpusManifest.seed`, single-sourced) + pin AND record the sklearn version** as an `outlier_model_version` / `sklearn_version` provenance field on the `OutlierResult` (and/or manifest-adjacent), analogous to the frozen `engine_version`/`model_version` discipline. Determinism is then *both* seed-fixed (within a version) *and* version-anchored (across time), so a replay knows the exact library it must match — consistent with constraint #7's version-anchored replay. `requirements.txt` already floors `scikit-learn>=1.5.0`; the FD pins the recorded-version discipline, NFR/Code-Gen pins the exact floor/lock. *(Recommended — the only option that makes reproducibility true across a dependency upgrade, matching how the rest of the system version-anchors replay.)*
- **B.** **`random_state` seed only**, treating the installed sklearn as fixed by the environment (no recorded version field). Simpler, and true *today*; but a silent sklearn upgrade could break reproducibility with no recorded signal — weaker against constraint #5's "100%".
- **C.** **Avoid the concern by not using a randomized estimator** — e.g. z-scores only (fully deterministic, no seed), dropping IsolationForest. *(Rejected — contradicts FR-OUT-1's explicit "z-scores + IsolationForest".)*
