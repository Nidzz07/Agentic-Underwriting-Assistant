# Tech-Stack Decisions — `ui-history` (U9)

**Stage**: BUILD → NFR Requirements (per-unit) · **Depth**: lighter (display) + INV-FAITHFUL + INV-NAMESPACE via StructuralGuard + focused teeth · **Unit**: U9 `ui-history` · **Date**: 2026-07-14. The **first UI unit with two READ operations in one seam** (WIRE-1 R6 list + R7 detail-by-id, both mocked), the **first** to render both namespaces (system `Recommendation` + human `CommittedDecision`) side by side, and the **first** with an **in-unit master-detail** navigation.
**Principle**: **inherit** ui-shell's frozen substrate (and the sibling units' applied convention) unchanged; name only what makes the `NFR-HIST-*` targets **checkable**; keep aesthetic values + bundler/deploy topology **deferred**. **No LLM. No live backend** (R6/R7 doubled). **No write path** (INV-FAITHFUL). Q1–Q3 all **A**.

## Decisions

| # | Decision | Rationale / notes |
|---|---|---|
| **D1 (inherited)** | **React + Tailwind CSS** | The pinned UI stack (FR-UI-5). `ui-history` lives at `frontend/src/history/`, composing frozen `ui-shell` primitives (incl. `ReadOnlyRegion` + `RecommendationBadge`/`ConfidenceBadge` for the system region). |
| **D2 (inherited)** | **Plain JS/JSX — NO TypeScript** | FR-UI-5; enforced by **NFR-HIST-NOTS-1** (no `.ts`/`.tsx`, no `tsconfig`). |
| **D3 (inherited)** | **Vitest + React Testing Library + jsdom** | Drives the component targets (SEPARATION-1, RULERESULTS-1, REASON-1, EMPTY-1, ERROR-1, VIEWONLY-1 render, DUALREAD-1, BACKPRESERVE-1, the seven per-state renders + consolidated transition of STATEMACHINE-1). Same runner as the frozen units — no new toolchain. |
| **D4 (inherited)** | **ESLint over the single `FORBIDDEN_TERMS` source** | Backs COPY-1 / ADVISORY-1 / TESTID-1 lints — **reuses** ui-shell's one word-list (no second list); each lint ships a **detector self-test** (non-vacuous). Mechanism **reused, not modified**: a **new `eslint.config.js` block** registers `no-inline-label` + `advisory-vocabulary` on `src/history/**` (mirroring the sibling blocks) + a `history-testid-convention` rule (mirroring `queue-testid-convention`). **No `src/shell` file modified.** |
| **D5 (inherited)** | **File / import / AST scan in CI (StructuralGuard convention)** | NFR-HIST-NOTS-1 (no `.ts`/`.tsx`), VIEWONLY-1 (no `RoleGate` import, **no router import**), **FAITHFUL-1** (no-write-seam), **NOSUPERSEDE-1** (no `status==='superseded'` branch / no `supersedes_decision_id` deref), PERF-1 (bounded reads). Mirrors the siblings' `nots` / `noRoleGateImport` / `noRouterImport` / single-call-site scans — **as a convention, not an import**. |
| **D6 (NEW) — R6/R7 dual-read double: one injected `historyFetchSeam` via prop (Q1-A / NFR-HIST-Fold-A)** | `HistoryView` receives its fetch object as a **prop** (`fetchSeam = { fetchList, fetchDetail }`, per the FD); production wires the real R6/R7 transport at the composition root, tests inject a **capturing dual-read double** with **two independently-capturing spies** (`fetchList.calls[i]=[page,size]`, `fetchDetail.calls[i]=[decision_id]`), each programmable/sequenceable. **One** double construction per suite, a **fresh instance per test** (the `ui-approval-gate` CG-Fold-1 pattern) + RTL auto-cleanup → count isolation. **Both operations are READS**, so — unlike U7/U8's asymmetric read+write double — there is **no "zero write calls before Confirm" gate**; the load-bearing count teeth are **read-attribution** (DUALREAD-1: select→`fetchDetail` only, page→`fetchList` only), **retry-targeting** (ERROR-1: listError→last page, detailError→same id), and **Back-triggers-zero-new-list-fetches** (BACKPRESERVE-1). |
| **D7 (NEW) — DOM-containment separation-teeth in jsdom (NFR-HIST-Fold-B)** | SEPARATION-1 (the load-bearing target) proves namespace-distinctness structurally via **`Node.contains()` + scoped `within()` queries** — jsdom implements `Node.contains()` for **arbitrary-depth** descendants (and `false` for a sibling's subtree), so `!system.contains(human)` / `!human.contains(system)` + `within(system).getByTestId('history-detail-recommendation')` present + `within(human).queryByTestId('history-detail-recommendation')` null (and the mirror for the human `action`) is a **sound sibling non-containment** assertion, not just parent-child. **Real teeth** (fails if a namespace were rendered in the other region). Mirrors `ui-memo-view` SEPARATION-1, applied to the two namespace regions. |
| **D8 (NEW) — BACKPRESERVE-1: before/after call-count snapshot, no double-side discrimination (NFR-HIST-Fold-2)** | The "Back adds zero new `fetchList` calls" teeth is a **simple before/after snapshot** of `fetchList.calls.length` taken immediately around the Back action **within a single test**, asserted equal (plus `page`/`items` identical). The **fresh-per-test double instance** already isolates counts across tests, so the double needs **no** special before-vs-after-mount discrimination — the snapshot is local to the one test. |
| **D9 (NEW) — `rule_results` disclosure: mounted-but-hidden + DOM-level query (Q3-A / NFR-HIST-Fold-C)** | The progressive disclosure collapses via the HTML **`hidden` attribute / `display:none`** (which **removes collapsed entries from the accessibility tree** — no separate `aria-hidden`) while keeping **every entry mounted** (INV-FAITHFUL). RULERESULTS-1's "all N present" assertion uses a **DOM-level query** (`getAllByTestId` / `container.querySelectorAll`) that finds mounted-but-hidden nodes — **not** a visibility-filtering `getByRole`/`getByText` query. The toggle (`history-detail-ruleresults-toggle`) is keyboard-focusable (A11Y-1). The concrete widget markup/animation is a Code-Gen detail; the **faithfulness + query contract** is pinned here. |
| **D10 (NEW) — advisory-vocabulary resolved by token-avoiding wording, verified against the REAL detector (Q2-A / NFR-HIST-Fold-D)** | HIST-Fold-4 is resolved **now** with **namespace-distinct human-region wording that avoids the standalone singular "decision"** ("Underwriter's committed action" / "Committed outcome"), so the reused `advisory-vocabulary` lint stays **unmodified and blanket** over `src/history/**` — **no new lint mechanism, no `src/shell` edit**. Verified against the **actual** `eslint-rules/index.js` `findForbiddenSystemOutput`: it is a **word-boundary** matcher, so **plural "decisions" and `decision_id` pass**, only standalone singular "decision"/`approved`/bare-`decline`/`declined` are flagged. Representative strings audited (all token-avoiding candidates clean; literal "Underwriter's decision"/"Decision history" correctly flagged). **Binding rule for Code-Gen**: static copy may use plural "decisions" freely but must avoid the standalone singular "decision" (title "History"/"Decisions", human region "Underwriter's committed action"). |
| **D11 (NEW) — `history-testid-convention` regex (queue-family)** | `^history-[a-z]+(-[a-z0-9]+)+$` (mirroring `queue-testid-convention` / the queue-family ≥3-segment shape), applied to `src/history/**` via the new eslint block; a `history-testid-convention` rule + self-test enforce it, incl. `history-row-<decision_id>` and the two region testids. |
| **D12 (NEW) — state-management mechanics: deferred to Code-Gen** | `HistoryView` holds `{ state, page, items, pageInfo, record, error }`; the **concrete hook/store shape**, request cancellation on rapid row switches, and the disclosure toggle wiring are **Code-Gen** mechanics. NFR pins only the **testable behavior** (the seven states, read-attribution, position-preserving Back, faithful rule_results), not the mechanism. |
| **D13 (inherited)** | **Node LTS + npm toolchain** | Frontend build toolchain is a Code-Gen detail; the **bundler/dev-server (Vite) + Vercel deploy topology stay DEFERRED** → `deploy-config` (P2) / confirmed at Infra Design (likely SKIP for `ui-history`). |
| **D14 (NEW) — deferred display values** | **aesthetic token values** (inherited from ui-shell tokens), the **exact profile-snapshot field subset** (`ProfileSnapshotRegion` — which `ApplicantProfile` fields to show), the **`rule_results` disclosure widget markup**, and **loading-placeholder markup** are **visual/tuning values deferred** to NFR-Design / Code-Gen — recorded as targets/shapes, not specified. |
| **D15 (inherited)** | **No new backend/runtime dependency; no LLM; no real network in tests; NO write path** | The history view composes frozen **value shapes** (WIRE-1 `DecisionSummary`/`AuditRecord`; `audit_store` schemas) and fetches R6/R7 through the double; the R6/R7 **route implementation** is WIRE-1/Build & Test, **not** authored here. It **imports no sibling-unit code** — their fetchSeam/StructuralGuard/testid-lint are **mirrored as a convention**. **No write/commit/mutation seam is introduced** (FAITHFUL-1). |

- **Concrete display values** (aesthetic token values, the exact profile-snapshot field subset, the `rule_results` disclosure widget markup, loading-placeholder markup) → NFR-Design / Code-Gen (D14).
- **The complete `history/copy.js` module** → Code-Gen (authored + lint-verified there); representative strings already verified against the real detector at this stage (D10 / NFR-HIST-Fold-D).

**No new dependency beyond the standard React/Tailwind/Vitest/RTL/jsdom/ESLint substrate already established by `ui-shell` and applied by the frozen sibling units; no LLM anywhere in `ui-history`; no live backend (R6/R7 doubled); no write path (INV-FAITHFUL); no `src/shell` edit and no sibling-unit import.**
